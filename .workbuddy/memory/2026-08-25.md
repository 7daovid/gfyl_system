## 第二批改动（按用户需求：默认通过/老师可调可删/时间段填报/取消合并）
- 模型变更：`records` 新增 `start_time`/`end_time`(TEXT HH:MM)；`schema.sql` 与本地库均已加列（`npx wrangler d1 execute qgzx-hours --local --command="ALTER TABLE ..."`）。
- 默认通过：新增 `DEFAULT_STATUS="approved"`（wrangler.toml [vars]），提交即自动通过；`approved_minutes=minutes`、`reviewer='系统自动通过'`。
- 时间段填报：`create.js` 改收 `segments:[{start_time,end_time,work_type_id,remark}]`，每条成独立记录；`util.js` 加 `isValidHHMM/toMinOfDay/slotMinutes/envStr`；最小时长 `MIN_SLOT_MINUTES="10"`；学生端可「＋新增时间段」批量提交；原"小时+分钟"下拉改为 `type=time step=600`。
- 老师端：每条可「调整工时」(改起止时间→重算 minutes 与 approved_minutes，需理由) 与「移除」(`admin/records/delete.js` 硬删+写不可删日志，需理由)；保留 驳回/撤销。
- 移除合并：`functions/api/admin/records/merge.js` 已删、admin.html/admin.js 合并 UI 全清；列表状态筛选去掉"已合并"。
- 学生 10 分钟自助改/删窗口放宽到 `pending`/`approved`（未驳回且未被管理员调过工时）均可。
- 测试结论：批量时段默认 approved、起止校验(结束晚于开始/≥10min)、匿名广场含 time_range、老师调整(需理由)与移除(需理由)、合并路由失效(405/401)、审计触发器仍生效(DELETE/UPDATE 报 SQLITE_CONSTRAINT)，全部通过 node --check + 端到端 curl/py 冒烟。
- 注意：旧 seed/历史记录无 start/end 时前端回退显示"填报时长"；`merge.js` 删除后该路径无 handler，admin.js 不再调用。
